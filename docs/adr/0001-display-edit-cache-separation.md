# 0001. 表示キャッシュと編集キャッシュの分離

- ステータス: 採択
- 日付: 2026-09-16（設計合意時点。実装前）
- 関連: `specs/offline-mode.html`、`CONTEXT.md`（表示キャッシュ / 編集キャッシュ）

## コンテキスト

現行のオフライン機構（IndexedDB v4）は、表示用データと整合権威フェンスを
単一のストア群に混在させており、表示のクリティカルパス上に
スコープ捕捉・権威 assert・キャッシュ保存・射影・公開検証が直列で乗っている。
結果として「オフライン機構なし時代（fetch → render）」より表示が遅く、
キャッシュ側の障害（`Offline cache scope invalidated` 等）が表示全体を
止める構造になっていた。

一方でノート本文のサーバー側権威は既に Yjs（DocumentRoom Durable Object）であり、
クライアントの協調編集も `Y.Doc` + `WebsocketProvider` で動いている。
自前の編集同期をもう一つ作るのは重複であり、規模が際限なく膨らむ。

## 決定

表示キャッシュと編集キャッシュを完全に分離する。

- **表示キャッシュ**: ノート一覧・フォルダ・本文スナップショット・画像の
  読み捨て可能なコピー。読み取り経路は `fetch → 表示` で、保存は detached。
  失敗は「未キャッシュ」に縮退し、オンライン表示を絶対にブロックしない。
- **編集キャッシュ**: ノート本文の Y.Doc を `y-indexeddb` で永続化。
  同期・マージ・再送はすべて Yjs / y-websocket に委譲し、自前の権威フェンスや
  マージ機構は持たない。ローカル永続化は「オフライン編集資格」を持つ
  ノート（所有者本人・実効書き込みスコープ self・編集ロックなし・
  過去に一度オンライン同期済み）に限定する。

## 検討した代替案

- 現行 v4 の権威モデルを段階的に緩和する → 複雑さの本体（両用途を1系統で
  扱う構造）が残り、編集の信頼性を自前で保証し続ける必要があるため不採用。
- 編集も OPFS スナップショットベースで自作同期 → Yjs と二重の真実が生まれ、
  マージ・コンフリクト処理を自前実装する必要があるため不採用。

## 影響

- 表示層の fail-closed 要件は「拒否の永続化」と「書き込み CAS」のみに縮退。
- オフライン編集可能範囲は本文編集のみ（作成は別途 Issue #118、
  削除・移動・共有・画像添付はオンライン限定）。
- 未送信 update を含むローカル doc は資格喪失・purge を問わず自動削除しない
  （purge はガードモーダル経由）。
