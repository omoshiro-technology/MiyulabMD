# 0002. 表示キャッシュ v4→v5 は全消去で移行する

- ステータス: 採択
- 日付: 2026-09-16（設計合意時点。実装前）
- 関連: `specs/offline-mode.html`、ADR 0001

## コンテキスト

表示キャッシュのスキーマ再設計（metadata の分割・epoch/権威機構の撤去）に伴い、
IndexedDB v4 から v5 への移行が必要になる。旧スキーマから新スキーマへの
データ写経（マイグレーションコード）は、書く・テストする・永遠に保守する
コストが大きい。

## 決定

upgrade 時に旧ストアを**全消去して空で継続**する。移行写経は書かない。

- 表示キャッシュは設計上「読み捨て可能」であり、次回アクセス時の
  ネットワークフェッチで再構築される。
- 拒否台帳まで消えても実害はほぼない。古いキャッシュ自体が消えるため
  「拒否済みデータの復活」は起きず、拒否は次回オンラインの 403/404 で
  再確立される。
- 編集キャッシュ（y-indexeddb）は新設の別 DB であり、移行対象は存在しない。

## 検討した代替案

- 拒否台帳のみ移行 → 台帳が参照する古いエントリ自体が消えるため効果が薄く、
  移行コードのコストだけ残るため不採用。
- 完全なスキーマ写経 → 読み捨て可能なデータに対して不釣り合いなコスト。

## 影響

- 既存ユーザーは一度だけキャッシュが吹き飛び、次回アクセスで再構築される。
  オフライン中のアップグレードでは「キャッシュなし」表示になり得る点は
  許容する（データ損失ではない）。
- v4 の権威フェンス・epoch 管理・suspend 機構は v5 では存在しないため、
  ロールバックするとキャッシュを再構築し直すことになる。
